# Security Policy

## Supported versions

Only the latest state of `master` is considered actively supported for security fixes.

## Reporting a vulnerability

Please report suspected vulnerabilities privately to the maintainers through GitHub security reporting features when available.

When reporting:

1. describe the issue and its impact clearly
2. include reproduction steps, affected files, and configuration details
3. avoid public disclosure until maintainers have had time to investigate and prepare a fix

We will aim to acknowledge valid reports quickly, reproduce the issue, and coordinate a fix before public disclosure.

## Disclosure expectations

- Do not open public issues for unpatched vulnerabilities.
- Give maintainers reasonable time to investigate and remediate.
- Keep proof-of-concept exploits private until a fix or mitigation is available.
